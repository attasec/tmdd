## ARCHITECTURE

- **cli_core** (cli_core): Argparse-based CLI entry point that parses user commands and dispatches to command handlers (src/cli.py, src/__main__.py)
- **init_engine** (init_engine): init command handler: scaffolds a new .tmdd/ project from a bundled template, substituting the user-provided name and description (src/commands/init.py)
- **lint_engine** (lint_engine): lint command handler: structural validation and cross-reference integrity checks over the loaded threat model, including mitigation reference resolution (src/commands/lint.py)
- **feature_engine** (feature_engine): feature command handler: drives the threat-model-first feature workflow and requests prompt generation (src/commands/feature.py)
- **compile_engine** (compile_engine): compile command handler: assembles the consolidated .tm.yaml and the secure-coding agent prompt from the full model (src/commands/compile.py)
- **review_engine** (review_engine): review command handler: maps a code diff to affected threats by matching changed files against component source_paths, and shells out to git for the changed file list (src/commands/review.py)
- **yaml_processor** (yaml_processor): Shared model-loading and path utilities: yaml.safe_load(), threat model assembly, and the glob-to-regex matching used by review (src/utils.py)
- **prompt_generator** (prompt_generator): Generates AI prompt text files for threat modeling and secure coding workflows (src/generators/threat_prompt.py, agent_prompt.py)
- **template_store** (template_store): Bundled YAML template files (minimal, web-app, api) used by init command for project scaffolding (src/templates/)
- **html_renderer** (html_renderer): Generates interactive HTML reports and architecture diagrams with embedded Cytoscape.js (report.py, diagram.py)
- **threat_model_store** (threat_model_store): The authored .tmdd/ YAML threat model itself - the input every command parses, and the injection vector behind prompt_injection, glob_redos and the stored-XSS threats. Excludes generated artifacts under .tmdd/out/
- **filesystem_store** (filesystem_store): Generated artifacts written by TMDD: consolidated .tm.yaml, prompt text files, HTML reports and diagrams (.tmdd/out/)
- **cdn_libraries** (cdn_libraries): External CDN (unpkg.com) serving Cytoscape.js 3.30.4, dagre 0.8.5, and cytoscape-dagre 2.5.0 loaded client-side in generated HTML
- **git_cli** (git_cli): External git executable invoked as a subprocess by the review command to list changed files (git diff --name-only). Not bundled with TMDD; resolved from PATH

- cli_core -> compile_engine: Parsed argparse Namespace for compile: model path, optional feature filter
- cli_core -> review_engine: Parsed argparse Namespace for review: model path, --base ref, --staged, --files, --repo-root, output format
- lint_engine -> yaml_processor: File paths to load; returns parsed YAML dicts for structural and cross-reference validation
- feature_engine -> yaml_processor: File paths to load; returns the parsed threat model used to build feature prompts
- compile_engine -> yaml_processor: File paths to load; returns the full parsed model for consolidation into .tm.yaml
- review_engine -> yaml_processor: File paths to load, plus component source_paths globs translated to regexes for changed-file matching
- html_renderer -> yaml_processor: File paths to load; returns the parsed model rendered into HTML report and diagram output
- yaml_processor -> threat_model_store: Read authored .tmdd/ YAML files (system.yaml, actors.yaml, components.yaml, features.yaml, data_flows.yaml, threats/*.yaml) via yaml.safe_load()
- template_store -> filesystem_store: Template YAML files with {{name}} and {{description}} placeholders substituted with user input, written to target directory
- feature_engine -> prompt_generator: Loaded threat model dict and feature metadata for threat-modeling prompt generation
- compile_engine -> prompt_generator: Loaded threat model dict for secure-coding agent prompt generation
- prompt_generator -> filesystem_store: Generated text prompt files (*.threatmodel.txt, *.prompt.txt) written to .tmdd/out/
- developer -> html_renderer: Standalone invocation of report.py / diagram.py with model path, output directory and output filename
- html_renderer -> filesystem_store: Generated HTML files (tm.html, diagram.html) with embedded JSON data and JavaScript, written to .tmdd/out/
- review_engine -> git_cli: git diff --name-only invocation carrying the user-provided --base ref/--repo-root; returns the list of changed file paths for the review command
- cdn_libraries -> report_viewer: JavaScript libraries (cytoscape.min.js, dagre.min.js, cytoscape-dagre.js) loaded via script tags from unpkg.com
- filesystem_store -> report_viewer: HTML report/diagram files served to browser with embedded threat model data in JSON format
- filesystem_store -> ai_agent: Generated prompt text files consumed by AI agent for threat modeling or secure code generation

## KNOWN THREATS
- [LOW] YAML template injection via init command name/description (yaml_template_injection): In src/commands/init.py:36-39, user-provided --name and --description values are substituted into YAML templates using simple str.replace() without escaping YAML metacharacters. A name containing newlines or YAML syntax (e.g., colons, brackets) could produce malformed or structurally altered YAML output files.
- [HIGH] Supply chain attack via CDN JavaScript dependencies (cdn_supply_chain_attack): report.py and diagram.py embed <script> tags loading from unpkg.com (cytoscape@3.30.4, dagre@0.8.5, cytoscape-dagre@2.5.0). If unpkg.com is compromised, a package is hijacked, or a MITM attack occurs, malicious JavaScript would execute in the report viewer's browser with full DOM access to the threat model data.
- [MEDIUM] Stored XSS via innerHTML in diagram JavaScript (xss_stored_diagram): In report.py's _DIAGRAM_JS (line 572+), the showFeature() function builds HTML strings from threat model data (threat names, descriptions, goals) and injects them via innerHTML. Although data passes through JSON.parse from an embedded <script> tag, YAML values containing HTML (e.g., <img onerror=...>) would be rendered as active markup in the viewer's browser.
- [MEDIUM] Stored XSS via innerHTML in node-info panel (xss_stored_node_info): In report.py's _DIAGRAM_JS, the cy.on('tap') handler for nodes and edges builds HTML strings using d.label, d.description, d.technology, and d.flowId directly, injecting them via info.innerHTML without HTML encoding. Malicious content in YAML component descriptions would execute as JavaScript.
- [MEDIUM] No audit trail for threat model modifications (no_audit_trail): TMDD stores threat models as plain YAML files with no built-in change tracking, signing, or attribution. Anyone with filesystem access can modify threats, mitigations, or feature mappings without a trace, undermining the integrity of the security assessment.
- [MEDIUM] Prompt injection via threat model content in generated AI prompts (prompt_injection): In src/generators/agent_prompt.py and threat_prompt.py, threat model data (threat names, descriptions, mitigation text) is embedded directly into AI prompt text without sanitization. A malicious actor who can edit YAML files could inject adversarial instructions into the prompt that alter the AI agent's behavior.
- [LOW] Script tag breakout in embedded JSON diagram data (json_script_breakout): In report.py:114, _safe_json() escapes </ to <\/ to prevent script tag breakout. However, other injection vectors (e.g., HTML entities, Unicode escapes) in threat model strings embedded in the <script type='application/json'> block could potentially bypass this single-pattern defense.
- [LOW] Report output path traversal via --name parameter (report_path_traversal): In report.py:1085, the --name argument is joined with the output directory via Path(out) / output_name without validation. Unlike diagram.py which uses safe_name() for filename generation (line 156), report.py passes the raw user input directly, allowing path traversal characters (e.g., ../../malicious.html) to write the HTML report outside the intended output directory.
- [MEDIUM] Regex denial of service via crafted component source_paths glob (glob_redos): In src/utils.py:92-127, glob_to_regex() translates a component's source_paths glob into a regex, mapping each '**' to '.*'. A source_paths value crafted with many wildcard segments (e.g. '**a**a**a...') compiles to a regex with many chained '.*' groups that exhibits catastrophic/polynomial backtracking when matched against long non-matching paths during 'tmdd review' (path_matches_any, src/utils.py:135). An attacker able to edit components.yaml can hang the review command (denial of service), which is especially relevant when review runs in CI over an untrusted branch's threat model.
- [LOW] Argument injection into git subprocess via --base ref (review_git_arg_injection): In src/commands/review.py:57, the user-supplied --base value is interpolated into the git revision argument as f'{base}...HEAD' and passed to git diff via subprocess.run (no shell, args as a list). The trailing '...HEAD' concatenation prevents a crafted --base from forming a clean leading option, so classic argument injection is largely blocked, but the ref is still handed to git unvalidated. In a CI context that forwards an untrusted PR ref into --base, unexpected revision resolution or errors are possible. Residual risk is low given the current suffix concatenation.
- [LOW] Mitigation reference path escapes repo root during lint (mitigation_reference_path_escape): In src/commands/lint.py:131, the reference-resolution check evaluates (repo_root / ref['file']).exists() without confining the path. Because pathlib resolves an absolute right-hand side to itself and does not collapse '..', a mitigations.yaml reference with an absolute path or '../' sequences is checked outside repo_root. The lint output ('file not found' vs silent) then acts as an existence oracle for arbitrary filesystem paths. An insider editing mitigations.yaml could probe for the presence of files outside the project.

## SECURITY CONTROLS
- yaml_escape_init_input: Escape or quote user-provided name/description values before substituting into YAML templates during init, using yaml.dump() or proper YAML string quoting to prevent structural injection
  - ref: src/commands/init.py:36-39
- sri_hashes_cdn: Pin CDN library versions with Subresource Integrity (SRI) hashes on all <script> tags in generated HTML to prevent tampered JavaScript from executing
  - ref: report.py:943-945
  - ref: diagram.py:143-145
- bundle_libs_locally: Bundle Cytoscape.js and dagre libraries locally instead of relying on CDN, eliminating the external dependency and enabling fully offline report viewing
  - ref: report.py:943-945
- replace_innerhtml_textcontent: Replace innerHTML assignments in _DIAGRAM_JS with textContent for plain text values, or use DOM createElement/createTextNode for safe HTML construction
  - ref: report.py:572-872
- js_html_escape_helper: Implement a JavaScript HTML-escape helper function in _DIAGRAM_JS and apply it to all threat model values (names, descriptions, labels) before inserting into HTML strings
  - ref: report.py:572-872
- git_change_tracking: Rely on Git version control for change tracking and attribution of .tmdd/ YAML files; document this requirement in README and generated AGENTS.md
- prompt_delimiters: Add clear delimiter markers and role boundaries in generated AI prompts to reduce the effectiveness of prompt injection from threat model content
  - ref: src/generators/agent_prompt.py:17-19
  - ref: src/generators/threat_prompt.py
- enhanced_safe_json: Enhance _safe_json() to escape additional dangerous characters beyond </ including HTML entities and ensure Content-Type is set correctly for embedded JSON data
  - ref: report.py:113-114
- validate_report_filename: Validate the --name output filename in report.py by stripping path separators and applying safe_name() or os.path.basename() before joining with the output directory, consistent with diagram.py's safe_name() approach
  - ref: report.py:1085-1088
- bound_glob_complexity: Cap the number of wildcard segments (and overall length) allowed in a component source_paths glob before translating it in glob_to_regex(), and/or match with a linear-time engine or a timeout, so a crafted pattern cannot cause catastrophic regex backtracking in tmdd review
  - ref: src/utils.py:92-127
- validate_git_ref: Validate the --base value against an allowed git ref-name pattern (or resolve it with 'git rev-parse --verify' and separate options from revisions using '--') before building the diff range in changed_files_from_git()
  - ref: src/commands/review.py:54-63
- confine_reference_paths: In the lint reference-resolution check, reject absolute reference paths and normalize the joined path (resolve/normpath) to verify it stays within repo_root before calling .exists(), preventing filesystem probing outside the project
  - ref: src/commands/lint.py:131-136
